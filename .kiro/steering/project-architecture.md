# Project Architecture

Structural rules for the youtube-studio repository.

## Repository Structure

```
youtube-studio/
├── studio/           # Reusable Manim utilities (grow organically)
├── pipeline/         # Automation scripts (batch operations, AI drafts)
├── assets/           # Shared assets (SVGs, fonts, music, sounds)
├── prompts/          # AI prompt templates
├── videos/           # One folder per video
├── catalog.yaml      # Master video index
├── manim.cfg         # Manim config
├── Makefile          # Utility commands
└── pyproject.toml    # Dependencies
```

## Video Production Model

**Each video = one self-contained Python file.**

```
videos/NNN_slug/
├── video_name.py    # Complete video (narration + animation)
└── assets/          # (optional) Video-specific SVGs
```

Render: `manim render -qh videos/NNN/video.py ClassName`
Output: `.mp4` + `.srt` (auto-generated by manim-voiceover)

## Technology Stack

| Component | Tool | Notes |
|-----------|------|-------|
| Animation | Manim Community Edition | Core rendering engine |
| Voice + Sync | manim-voiceover + GTTSService | Auto voice-animation sync |
| Voice quality | GTTSService (free) | Upgrade to ElevenLabs/Kokoro later |
| Subtitles | Built-in (manim-voiceover .srt) | Auto-generated during render |
| Config | 1920x1080 @ 60fps | YouTube standard |

## Key Dependencies

```
manim>=0.18.0
manim-voiceover>=0.4.0
gtts
sox (system package)
ffmpeg (system package)
```

## What the Pipeline is For

The `pipeline/` directory and `produce.py` serve batch/AI operations:
- Research topic → generate narration draft
- Batch-scaffold new video folders
- NOT for final video rendering (that's just `manim render`)

## Git Strategy

- Feature branches → PR → merge to main
- Branch naming: `feat/`, `fix/`, `video/`
- Rendered video files: NEVER committed (gitignored)
- Video .py source files: ALWAYS committed
- Branch protection on main: require CI (Validate & Lint) to pass

## Scalability

- Video numbering: 001-999, never renumber
- One folder per video, flat structure
- catalog.yaml for metadata/search
- Reusable patterns extracted to studio/ after 3+ uses
